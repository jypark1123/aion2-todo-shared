# 1. 주 담당자 (리딩) 업무

# [마일스톤 시작 전]
ㄴ마일스톤 기간 내 전체 업데이트 스펙을 파악하고 테스트 계획을 수립한다.
ㄴㄴ내부 환경 세팅
ㄴㄴㄴ내부 빌드노트 시트 생성: 개발팀 작업내역을 보고 우리 빌드노트에 N차별로 적재해 옮겨놔야 한다.
ㄴㄴㄴbugs.xlsx 업데이트(업로드): TestTrack(JIRA) 이슈를 항상 최신화해야 빌드노트에 연결된 이슈 목록을 최신 내용으로 가져와 실무자들이 빠르게 내용 파악(URL 링크로 바로 이동)이 가능하다.
ㄴㄴ외주 빌드노트 시트 생성
ㄴㄴㄴAir에서 마일스톤 업데이트 스펙 내보내기: 외주에서 담당 영역 볼륨 확인 및 사전 QA할 수 있도록 정보 제공하기 위함이다.
ㄴ주요 스펙을 검토하고 규모에 따라 영역별 담당자와 점검QA/심사QA 담당자를 지정한다.
ㄴㄴ선정 기준: 사람들의 피로도, 남은 근로 시간 등을 고려하여 영역 담당자 선정
ㄴㄴ주차별 근무표 참고: AION2_근무일지.xlsx(https://ncsoftcorp.sharepoint.com/:x:/r/sites/pre_aion2qa/_layouts/15/Doc.aspx?sourcedoc=%7BC237F015-AB1C-48FD-BFE6-FF2D42E00763%7D&file=AION2_%25uadfc%25ubb34%25uc77c%25uc9c0.xlsx&action=default&mobileredirect=true)
ㄴ외주 업체에 요청할 업무를 선정한다. (외주 실무 참고: https://nckorea.atlassian.net/wiki/spaces/AION2QA/pages/1004142594?xpis=eyJicmlkZ2UiOiJzbWFydExpbmtzIiwiaWQiOiIxNzg3NzMzODM4MDg0Iiwic291cmNlIjoiY29uZmx1ZW5jZSJ9)
ㄴㄴ1단계: 내부에서 진행해야 할 주요 일감을 선정하고, 그 외 일감은 기본적으로 외주에서 진행한다는 생각으로 접근한다. 
ㄴㄴ2단계: 1단계 과정을 통해 선정된 외주 진행 일감들을 리뷰하며 최종적으로 요청 업무를 결정한다.

# [마일스톤 진행 중]
ㄴ주요 스펙 담당자와 테스트 커버리지를 협의하고, 테스트에 필요한 요청사항을 검토한다.
ㄴNC QA 업무 지원 요청이 필요한 일감은 각 부서와 협의한 프로세스에 따라 업무를 요청한다.
ㄴㄴ호환성QA팀: “A2QA_호환성QA” 채널로 업무 요청
ㄴㄴ플랫폼연동QA팀: “A2QA_플랫폼QA” 채널로 업무 요청
ㄴㄴ플랫폼서비스QA팀: 메일을 통해 업무 요청 (받는 사람: 최민영, 참조: 홍지혜)
ㄴㄴ퍼플QA팀: 내부 담당자(유형준 검토) 후 필요 시 요청
ㄴㄴCQA팀: “CQA_AION2” 채팅방을 통해 업무 요청 (네트워크 관련 버그 수정은 CQA에서 확인, 그 외 버그 수정은 내부에서 확인하는 것으로 협의됨 ㄴ26년 1월)
ㄴ빌드 배포 일정을 트래킹하고, 배포 범위(특히 서버)에 대해서 PM팀과 협의한다.
ㄴ개발 마감이 되면 빌드 노트를 내부 문서에 작성하고 일감별로 담당자를 산정하고 QA 일정을 산정한다.
ㄴㄴ빌드 노트 작성 가이드는 본 페이지 하단을 참고한다.
ㄴㄴQA 일정 산정이 완료되면 진행상황 시트에 완료 시간과 코멘트를 작성한 뒤 PM팀에 공유한다. (진행 양식은 진행상황 시트 참고)
ㄴㄴ만약 일정 산정 시점과 실제 QA 시작 시점에 차이가 있는 경우 QA 시작 시점에 시작 사인을 전달한다.
ㄴ주요 스펙 진행 현황: 개발팀 빌드 노트 직접 작성
ㄴ빌드 노트에 누락된 수정 버그에 대한 수정 확인이 누락되지 않도록 주기적으로 확인 및 업무를 요청한다.
ㄴㄴ버그 필터: “차수별 빌드가 배포될 때마다 수정 버전을 수정하여 저장해야 함” 그래야 버그 누락을 방지할 수 있음.
ㄴ주요 버그(테스트 블록, 심각도 2이상, 클라이언트 버그)는 PM팀에 별도 공유하며 빠른 수정을 요청한다.
ㄴ결과 리포트 작성(클라이언트 일감 마감 시점 1회, 전체 일감 마감 시점 1회로 총 2회 작성한다.)
ㄴㄴ결과 파일 업로드 공간(NC QA Share): 쉐어포인트(https://ncsoftcorp.sharepoint.com/sites/QACenter_Share/Shared%20Documents/Forms/AllItems.aspx?id=%2Fsites%2FQACenter%5FShare%2FShared%20Documents%2FAION2%5FQA%2F%EA%B2%8C%EC%9E%84QA&viewid=c40d7935%2Dbcf5%2D48cc%2Da62c%2D2638f0ea46c0&CID=d4a72476%2Dda06%2D4cf9%2Da32a%2D039077fd6e65&FolderCTID=0x01200086CD5094C1C66340B8800EC99AAFAA75)
ㄴㄴ결과 리포트 버그 목록 정렬 기준: Severity(오름차순) -> 상태(Opened -> Verify Failed -> Fixed -> Closed)
ㄴ고객 제보나 PM팀에서 긴급한 라이브 이슈가 전달되면 담당자를 지정 및 업무 대응을 한다.
ㄴㄴ현재 봇을 통해 나누고 있지만, 첫 번째 담당자가 바쁠 경우 다른 담당자를 지정해줘야 한다.
ㄴ[월요일] 스킬 영역 플레이 테스트 일정을 조율을 한다. 헥토(외주)에서 스킬 확인을 많이하기 때문에 내부에서 예외사항을 커버하기 위함이다.
ㄴ[화요일] 점검 관리 사이트에 티켓이 추가되면 담당자/예정 업무/점검 시간을 작성한다.
ㄴ근무 일정 조율
ㄴㄴ업무 진행 상황에 따라 퇴근 시점과 추가 대응 인원을 선정한다.
ㄴㄴ점심/저녁 식사 전 긴급한 업무가 생길 경우 업무 대응 및 식사 일정을 조정한다.
ㄴㄴ업데이트 목표 대비 전체 진행률이 낮은 경우 주말 출근 필요성에 대해 검토한다.

# 2. 부 담당자(부리딩) 업무
ㄴ업무 요청: 차수별 빌드 노트가 작성되면 헥토큐앤엠 일감의 개수를 안내하고, 테스트에 필요한 자료(에어 티켓, 기획서, 데이터 파일 등)를 전달한다.
ㄴ문의 사항 대응: 빌드 노트(외주 업체) > 문의 시트에 있는 내용을 확인한 뒤 답변한다.
ㄴ결과 기록: 외주 업체가 진행한 테스트 결과를 리뷰(누락/보완할 케이스가 있다면 추가 요청)한 뒤 빌드 노트(내부)에 기록한다.
